# 产品插槽契约

kit 只认这一页写的东西。产品层交齐了，kit 一行都不用改。

分三份：`config.js` 的行为数据、`rig.js` 的几何、`index.html` 的 DOM 骨架。

---

## 一、rig.js

```js
export function createRig({ renderer }) {
  return {
    root,      // THREE.Object3D，整机挂在它下面
    bounds,    // { top, bottom, halfW } —— 世界坐标，取景和地面高度都靠它
    parts,     // [{ name, g, off }] —— 拆解与标注的锚点
    joints,    // [THREE.Object3D] —— 需要「挑最近一颗」的锚点（可选）
    mat,       // { 名字: Material } —— init() 里要改的材质（可选）
    tilt,      // 弧度 —— 零件层相对世界绕 Z 的倾角，拆解要做反向补偿（可选）
  };
}
```

| 字段 | 谁在用 | 说明 |
|---|---|---|
| `bounds.top/bottom` | `stage.js` 算地面高度、`framing.js` 算取景距离 | 竖直方向的极值，不是包围盒中心 ± 半高那么简单，量出来填 |
| `bounds.halfW` | `framing.js` | 横向半宽，决定拆解态要多远才装得下 |
| `parts[].g` | `explode.js` 平移、`callouts.js` 挂锚点 | 一个可独立移动的零件层（外壳、内核、端盖……） |
| `parts[].off` | `explode.js` | 该层沿哪个方向推开、推多远。`off` 是**拆解位移**，不是装配偏移 |
| `tilt` | `explode.js` | 层绕 Z 有倾角时，沿局部轴推出去会产生向下的分量，要按 `off.z·k·sin(tilt)` 反补 |
| `joints` | `callouts.js` 的 `kind:'joints'` | 左右对称的小件，每帧挑离相机近的那颗 |

`renderer` 用来问最大各向异性（`renderer.capabilities.getMaxAnisotropy()`），做贴图时用。
如果你的 rig 不建纹理，可以忽略这个参数。

**网格约定**：`createRig` 返回前，所有网格必须已经建好 —— `look.js` 会在构造时把材质
记下来，之后才挂上去的网格 X-RAY 模式会失效。网格要设 `castShadow = true`。
**不要用 `visible = false` 隐藏网格**（见坑 2），要隐藏请用 `layers`。

### 一·补、用模型文件（OBJ）

不想用代码搭几何，可以直接拿模型文件。`kit/objrig.js` 的 `buildObjRig` 把模型
转成上面那套结构：

```js
import modelText from './model.obj';
import { buildObjRig } from '../../kit/objrig.js';

export function createRig() {
  return buildObjRig(modelText, {
    height: 2.0,                            // 归一化后的目标高度
    up: 'y',                                // 模型原本的「上」方向（'y' 或 'z'）
    layers: ['housing', 'core', 'cap'],     // 参与拆解的装配名
    explode: { cap: [0, 1.35, 0] },         // 每层的拆解位移
    materials: { housing: { color: 0xb9b4aa, roughness: 0.58, metalness: 0.16 } },
  });
}
```

它替你做了三件事：

| 做什么 | 为什么 |
|---|---|
| 归一化（缩放 + 居中） | CAD 导出的单位不统一（毫米/厘米/英寸都有），不归一化的话取景算出来的相机距离会离谱 |
| 装配 → 层 | OBJ 的每个 `o` / `g` 分组变成一个 `parts` 层。loader 的 group 被**再包一层** `THREE.Group`，平移层不会动到 mesh 的局部坐标 |
| 材质统一 | OBJ 给的是 `MeshPhongMaterial`，没有 metalness / roughness，影棚灯光下会显得很平。转成 `MeshStandardMaterial` |

**模型必须按部件分组**。爆炸图的「层」来自 OBJ 的分组，一个整体模型只能展示、拆不开。

**顺序有讲究**：归一化必须在装配结构搭好之后做。归一化改的是 `root` 的
position / scale，而拆解层是从 `root` 里「搬」装配出来的 —— 先归一化再搬，
被搬走的装配就脱离了被缩放的 `root`，缩放会丢（模型没被缩放，取景就错位）。

`buildObjRig` 额外返回 `meta`（`assemblies` 装配名列表、`scale` 缩放系数、
`size` 归一化后的尺寸），方便写 `config.js` 时对照。

**GLB / glTF 不支持** —— 解析是异步的，而 `createRig()` 必须同步返回。
构建期把模型转成 OBJ 即可。

## 二、config.js

```js
export default {
  name: 'SAMPLE',
  qaGlobal: 'DOSSIER',                      // window.DOSSIER 露出的调试钩子名（可选）
  clock: { duration: 12, omega: 0.35 },     // 转台一圈几秒、角速度
  views: { hero: { yaw: 0.46, pitch: 0.11 }, /* … */ },
  explode: { slideOffsets: { sleeve_1: -0.55 } },
  framing: { maxPush: 1.35 },
  callouts: [ /* 见下 */ ],
  hud: { lane: {}, layers: ['BASE', 'SHAFT'] },
  createRig,
  init({ product }) { return { tick(dt) {} }; },   // 可选
};
```

### 必需字段

`views`、`explode`、`callouts`、`clock`、`createRig`。
`framing`、`hud`、`init`、`qaGlobal` 都是可选的 —— 不给就走 kit 的默认值。

### views

`{ [name]: { yaw, pitch } }`。`yaw` 是**相对转台当前角度**的偏移，切预设时会把
`spinA` 加上去 —— 转盘停在哪儿，按下去都对得上同一个视角。`pitch` 是绝对俯仰（弧度），
`0` 平视、`1.02` 约 58°。

按钮通过 `data-view="hero"` 找它，名字要和 `index.html` 里的一致。

### explode

| 字段 | 默认 | 说明 |
|---|---|---|
| `slideOffsets` | `{}` | 不参与整体平移、只沿装配轴滑一小段的层：`{ 层名: y 位移 }` |
| `k` | `framing.exK` | 最大外扩倍率，`off` 先乘它再乘进度 |
| `tyPush` | `-0.115` | 拆开时注视点上移多少（＝产品往画面里推） |
| `facePitch` | `0.04` | 拆开时顺手转正到的俯仰 |

`slideOffsets` 里的层只走 y 轴位移（`p.g.position.set(0, by·k, 0)`），
其余层走 `off` 的三轴位移。

拆开时镜头会自动转到正对产品，因为 3/4 视角下最外侧那摞会伸到面板底下。

### framing

| 字段 | 默认 | 说明 |
|---|---|---|
| `maxPush` | `2.0` | 取景预留的爆炸行程。**必须等于产品最大的 `off`** |
| `exK` | `0.68` | 最大外扩倍率。实际位移 = `off × exK × 进度` |
| `baseTY` | `-0.165` | 相机看向的 y。调小 = 产品在画面里上浮 |
| `fill` | 见 `kit/framing.js` | 各断点的填充比例 |

`maxPush` 留少了，拆开的零件会飞出画面；留多了，产品缩得太小。

### callouts

```js
{ no: '01', label: 'CROSS RAIL', zh: '横梁', side: 'left', dy: -118,
  anchor: { kind: 'root', at: [0, 0.56, 0] } }
```

| 字段 | 说明 |
|---|---|
| `no` | 左上角编号，`01`… |
| `label` / `zh` | 英文名 + 中文名，两行 |
| `side` | 初始栏位；实际会按屏幕位置自动换边 |
| `dy` | 屏幕上的竖直偏移（像素）。手机上会乘 0.55 |
| `hidden` | **只把引线画成虚线**（隐藏件的制图惯例）。标签照常显示，它不负责淡出 |
| `anchor` | 见下表，四选一 |

| `anchor.kind` | 参数 | 用途 |
|---|---|---|
| `root` | `at: [x,y,z]` | root 局部坐标里的一个点。适合横梁这种整体件 |
| `part` | `name`, `lift?` | 挂在某个零件层上，拆解时跟着层飞走 |
| `parts` | `names[]`, `normals[]`, `facing`, `lift?` | 左右各有一层，按层法线挑朝向观众的那只 |
| `joints` | `joints: [0,1]` | 球这类没有固定法线的小件，挑离相机最近的 |

`parts` 里的 `normals` 是该层在装配态下的朝向（`-1` 朝 −x，`1` 朝 +x），
`facing` 表示「这个零件长在哪一面」（内层朝中轴是 `-1`，外壳朝外是 `1`）。
`names` 与 `normals` 的**长度必须相同**。

为什么不能按距离挑：左右两层的到相机距离几乎一样，按距离会五五开乱跳。
为什么不能按「锚点相对产品中心的方向」判前后：内层零件长在朝中轴那一面，
人在 +x 侧看它，它的位置却在 −x 侧 —— 用位置方向会把唯一可见的内层判成背面。

**层法线要跟着转台转**：挑朝向观众的那一层时，法线的世界分量是
`(s·cos(spinA), 0, −s·sin(spinA))`。直接拿未旋转的 `s` 去点积，等于假设转台没转过 ——
非零 spin 时会挑中背对相机的那一层，标注指着看不见的零件自己先灰掉。
实现见 `kit/callouts.js` 的 `update()`。

### hud

```js
hud: {
  lane: { samples: 300, width: 600, base: 18 },   // 时间轴波形：合成曲线的参数
  layers: ['BASE', 'SHAFT', 'HOUSING'],            // 右下层叠图的层名（只做 tooltip）
}
```

波形是示意曲线，不是真实信号。要接真数据，改 `kit/hud.js` 的 `drawLane()`。
`layers` 最多 10 条（再多了同心圆半径会变成负数）。

### init（可选）

产品专属逐帧逻辑放这里，比如贴图动画。返回 `{ tick(dt), dispose() }`。

```js
init({ product }) {
  const tex = makeSomeAnimatedTexture();
  product.mat.visor.emissiveMap = tex;
  return { tick(dt) { tex.needsUpdate = true; } };
}
```

`tick` 用固定 `dt` 驱动，和主循环同一个时钟 —— 换真实数据源时不要在里面读
`performance.now()`，否则录制出来的曲线和页面上看到的不是同一条。

## 三、index.html 的 DOM 骨架

kit 靠 id 找元素。缺一个不会崩，但对应的功能会静默失效。

| id | 用途 |
|---|---|
| `gl` | WebGL canvas |
| `mast` | 顶部标题块。手机上用它算产品可用区域的**上界** |
| `controls` | 控制簇。手机上用它算**下界**，桌面是右侧竖排 |
| `views` / `modes` / `envsw` | 三组按钮容器，靠 `data-view` / `data-mode` / `data-env` 认按钮 |
| `btn-explode` / `btn-callouts` | 拆解 / 标注开关（单按钮，靠 `.on` 表示状态） |
| `play` / `status` | 播放键与待机状态文字 |
| `lane` / `head` / `headDot` / `tn` | 时间轴轨道、播放头、时间读数 |
| `waveA` / `waveB` / `ticks` | 波形两条曲线与刻度 |
| `stackRow` | 层叠图容器（内容由 kit 生成） |
| `labels` / `leaders` | 标注文字层、引线 SVG 层 |
| `loading` | 首屏遮罩，加 `.gone` 淡出 |

按钮的类名也是契约：`.btn` 普通、`.btn.on` 选中。样式全在 `app/dossier.css`，
改版式改那一个文件。

**手机端只能改样式，不能删 DOM 节点** —— `main.js` 每帧还在往 `#head` /
`#headDot` / `#tn` / `#waveA` / `#stackRow` 里写东西，删了就是 null 引用。
要藏起来用 CSS `display:none`。

**不要在 CSS 里另写媒体查询**。窄屏判据统一由 `main.js` 的 `resize()` 判定，
结果打在 `body.m` 上。两套判据一定会互相打脸。

## 四、产品槽怎么选

`src/app/main.js` 里这一行是**占位路径**：

```js
import product from '../products/slot/config.js';
```

构建脚本（`tools/build.mjs`）把它重定向到 `src/products/<选中>/config.js`：

```bash
npm run build -- --product obj-demo
npm run build -- --product obj-demo --out examples/my-product/dossier.html
```

不传 `--product` 就用 `tools/build.mjs` 里的 `DEFAULT_PRODUCT`（当前是 `sample`）。

**为什么用重定向而不是在源码里写死产品名**：

- 换产品不改源码 —— `git diff` 里不会出现与产品无关的改动
- 只有被选中的那一个产品模块进 bundle —— 别的产品的模型文件整块被 tree-shake 掉，
  产物不会因为「多了一个产品槽」而白白变大

**新增一个产品槽**：建 `src/products/<name>/`，里面放 `config.js` + `rig.js`
（+ 可选的模型文件）。不用改 `main.js`，也不用在任何地方登记 —— 槽是目录，
`--product <name>` 直接就能用。

## 五、调试钩子

`window.<qaGlobal>`（默认 `DOSSIER`）：

```js
DOSSIER.ready                 // 首帧好了
DOSSIER.seek(t) / pause() / play()
DOSSIER.setMode('clay' | 'xray' | 'shaded')
DOSSIER.setEnv('paper' | 'dark')
DOSSIER.setExplode(true) / setLabels(false)
DOSSIER.setView('top')
DOSSIER.settle()              // 相机与拆解缓动一次性贴到目标（截图必用）
DOSSIER.exK                   // 当前拆解进度 0..1
```

`settle()` 不是锦上添花：无头浏览器只有十几帧每秒，靠插值到位要等好几秒，
不贴住就截到半路状态。所有截图脚本第一步都是 `pause(); seek(0); settle()`。

钩子上还挂着 `THREE / scene / camera / renderer / product / anchors / camDir /
layout / orbit / explode / theme / look / hud`，排查问题时直接读。
