# 踩过的坑

这些是本项目代码里留下的每一条注释的正文。每一条都真的踩过、都花过小时级的时间，
写在这里是为了省下一次排查。

按代价从大到小排。

---

## 1. 边线必须是 mesh 的子对象

X-RAY 模式画的是硬边轮廓（`EdgesGeometry`，折角 > 26° 才留）。
第一版的做法是把每条边的 `matrixWorld` 预烘成静态几何，挂到转台下面。静止时完全正常。

一拆解就露馅：实体在飞、线不动，画面里出现两套错位的轮廓；收拢之后，
拆解位置的「幽灵零件」还留在原处。

挂成 mesh 的子对象，线天然跟随旋转和拆解，一行变换代码都不用维护。

## 2. 关实体不能用 `visible = false`

X-RAY 要把实体藏起来只留线。直觉是 `mesh.visible = false` —— 结果是整台产品消失，
连刚挂上去的边线也没了。

three 的 `projectObject` 遇到 `visible === false` 直接 `return`，整棵子树一起跳过。
边线是子对象，所以一起被跳过了。

改用 `layers`：实体扔到 layer 1（相机只看 0），边线留 0。可见性由相机控制，
子树照常遍历。

## 3. `1fr` 不是等宽

`grid-template-columns: 1fr 1fr` 里的 `1fr` 实际是 `minmax(auto, 1fr)`。
内容宽的那一格会把轨道撑开，同一行按钮宽度实测参差不齐，卡片右边缘像被啃过。

要真等宽写 `repeat(2, minmax(0, 1fr))`，再给文字容器
`overflow: hidden; text-overflow: ellipsis` 兜底。

配套的坑：等宽之后 81 px 里塞不下「图标 12 + 文字 + 编号 9 + 两个 6 px 间隙」，
较长的按钮名立刻被截断。截断比参差更难看。手机端最后是把编号去掉，
字号按实测定到 7.5 px / 字距 .02em。

## 4. 漏了 `viewport-fit=cover`，`env(safe-area-inset-*)` 恒为 0

底部控制条写了 `padding-bottom: calc(9px + env(safe-area-inset-bottom))`，
在 iPhone 上仍然贴着屏幕下沿、压着 Home 手势条。

原因在 `<meta name="viewport">` 少了 `viewport-fit=cover`。没有它，iOS 不给安全区数值，
`env()` 一律返回 0，`calc` 等于只有那 9 px。

这一条不加，后面写多少 `calc` 都是摆设。

## 5. esbuild 会把 `$` 和 `$$` 合成同一个标识符

工具函数从 `jquery` 那套习惯抄来：

```js
export const $ = (sel, root = document) => root.querySelector(sel);
export const $$ = (sel, root = document) => Array.from(root.querySelectorAll(sel));
```

打包之后两行都变成了 `var $ = ...`，`$('#gl')` 拿到的是一个**数组**。
表现是 `new WebGLRenderer` 抛 `canvas.removeEventListener is not a function` ——
因为数组没有这个方法。真正的错误在这条之下，被掩盖了。

改名叫 `one` / `all`。名字短不值得，这类 bug 找一次两小时。

## 6. 拆解时零件会往下沉，要按倾角反补

零件层沿自己的局部轴推出去，如果这一层绕 Z 有 10° 倾角，位移会被投影出一个向下的分量。
最大那一层沉 `off.z × k × sin(10°) ≈ 0.24`。

不补的话整张爆炸图是一条向下的斜线，最外侧两层还会戳进地面。
按同样的量在 y 上加回去就行，公式在 `kit/explode.js` 的 `apply()` 里。

## 7. 拖拽的基准是 `view`，不是 `goal`

拖拽要接住「镜头现在实际在哪」。如果基准取 `goal`（缓动目标），预设视角的补间还没跑完
就按下鼠标，画面会先跳到终点再跟着手走 —— 像镜头被弹了一下。

`kit/orbit.js` 里按下那一刻把基准改成 `view.yaw / view.pitch`，松手才把 `goal` 拉过去。

配套一条：**拖拽路径不要用 `easeIO`**。easeInOutCubic 的峰值速度是均值的三倍，
1.5 s 的摆动会把手抖也放大成甩镜。拖拽用指数逼近（`lerp` 按帧率无关的系数），
只给「切预设」用 `easeIO`。

## 8. `setFromObject` 之前必须刷新世界矩阵

标注要算「锚点附近那摞零件占多大」，取的是 `Box3.setFromObject(part.g)`。
矩阵还没刷新时它读到的是上一帧（甚至是单位矩阵）下的包围盒，位置一偏，
引线就指到空处 —— 而产品静止时看起来完全正常，只有转起来才露。

在 `renderer.render()` 之后、或者取包围盒之前显式
`root.updateMatrixWorld(true)`。`kit/callouts.js` 的 `build()` 里有这一步。

## 9. `setViewOffset` 的 y 传负值才是向下

手机要把取景窗整体上移，让产品躲开底部 dock。写的是：

```js
camera.setViewOffset(w, h, -ox, -oy, w, h);   // y 传 −oy ⇒ 画面内容位移 +oy（向下）
```

符号反了产品就往反方向跑，而且看起来「只是偏了一点」，很容易以为是 `fitDist` 算错。

## 10. 标签宽度缓存必须在字号变化后作废

手机端标注要贴边，右栏用 `right: 10px` 定位，引线的终点要减去标签宽度。
宽度用 `offsetWidth` 缓存。

两个时刻必须清零：`resize()` 里破了窄屏开关之后（字号变了），
以及 `setLabels(true)` 时（隐藏期间 `offsetWidth` 是 0）。不清零就拿 0 去算，
引线全部穿过文字。

## 11. 每帧写 `style.opacity` 会打断 CSS 过渡

标注淡入淡出靠 CSS `transition`。但主循环每帧都在写 `opacity`，
浏览器的过渡被打断，表现是「没有过渡」。

做法是记录上一次的值，只有真的变了才写。`kit/callouts.js` 里那个 `a._k` 就是干这个的。

## 12. 暗场不是把背景调暗

第一版暗场只是换了背景色，结果产品跟着一起黑掉。

正确的做法是同时改六样：环境贴图（深底 + 高对比 strip）、直射光配比、曝光、
地面接影、刻度盘、线框颜色。深底上浅色外壳必须靠一道亮轮廓跟背景分开，
所以暗场的 key / rim 反而比纸面**更亮**。

细节有两处：

- 暗场里 X-RAY 的边线必须往亮里走，否则深灰线画在近黑底上，整台产品只剩一团影子。
- 「浅」在纸面和暗场是**两个方向**，不能一条公式套过去。纸面是「往白里兑 + 提不透明度」，
  暗场是「往黑里兑 + 降不透明度」—— 照抄纸面那套会让刻度盘变成一圈发光灯带。

## 13. 双指缩放要自己写，`touch-action` 要写在根上

手机上没有滚轮，`wheel` 那套缩放等于不存在。而 `#gl` 上写了 `touch-action:none`，
浏览器原生捏合也被挡掉 —— 两根手指按下去**什么都发生不了**，是纯粹的空白地带。

要自己接：指针记在 `Map` 里，1 根环视、2 根按 `span` 比例改 `dist`。
三条判据缺一不可：

- **`touch-action:none` 只写 canvas 不够**。pinch 起手时只要有一根手指落在
  dock / 标注这些上层元素上，浏览器就按页面缩放处理：整页放大，`overflow:hidden`
  又退不回去。全屏应用没有滚动，直接在 `html,body` 上关掉全部原生手势。
- **松回单指要用剩下那根手指的位置重建基准**，否则相机被旧基准拽一下。
  基准角度取 `goal` 不取 `view`（此时 tween 必为空）：取 `view` 会把还没收敛完的
  那点差距当成基准误差，手指一动画面先往后退一格。
- **捏合基准距离取 `goal.dist` 不取 `view.dist`**：`view` 是还在收敛的显示值，
  拿它当基准会把上一段缩放的零头退回去 —— 手指没动，产品自己退一点。

配套一条容易漏的验收：**双指平移（间距不变）不能改 `dist`**。写成
`goal.dist += (span - last)` 这类增量式就会漂，用「基准 span × 比例」这种绝对值写法才不会。

## 14. 层法线必须跟着转台转

左右各有一层同名零件时（外壳、内核……），标注要跟着「当前朝向观众的那一层」走。

挑的时候要用**旋转后**的法线：法线在装配态是 `(s, 0, 0)`，转台转过 `spinA` 之后，
世界分量变成 `(s·cos(spinA), 0, −s·sin(spinA))`。

直接拿未旋转的 `s` 去和相机方向点积，等于假设转台没转过。转台一直在转，
于是绝大多数角度下都会挑中**背对相机**的那一层：引线指着看不见的零件，
而那一侧的标注又因为「在背面」被自己压暗 —— 画面上就是一根指向空白、
文字还灰着的引线。

判断前后（决定要不要淡出）用的是旋转后的法线，挑层用的却是未旋转的 ——
两处必须用同一个公式，否则挑出来的层和判出来的背面互相矛盾。
实现见 `kit/callouts.js` 的 `update()`。

**验收方式**：把时间 `t` 从 0 扫到一个整圈（12 s），每一步比对
「标注当前挂的那一层」和「法线朝向相机的那一层」是否一致。
只测转台角度为 0 的那一帧是测不出来的。

## 附：来自上游项目、本仓库代码里没有的两条

这两条不在 `src/` 的注释里（本仓库的几何没用到），但同类做法一定会撞上，
存档备查：

**`polygonOffset` 要写负值。** 给外壳加线框、两者贴得太紧会 z-fighting。
写正值时被深度测试逐像素判掉，`visible === true` 却一个像素都不出 ——
很容易往参数方向上想歪。

**`Object3D.clone()` 会深拷 `userData`。** 如果 `userData` 里塞过 Material，
Material 有循环引用，`clone()` 直接抛栈溢出。只复制变换就自己写
`position / quaternion / scale`，或者 `Object3D.prototype.copy.call(target, source)`。
